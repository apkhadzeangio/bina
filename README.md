# ბინის დიზაინერი

ბინის ზუსტი გეგმა → მასალები და 3D → ხარჯთაღრიცხვა.

## ფაილები

- `dist/site/index.html` — მზა გვერდი Cloudflare-ზე ასატვირთად (ერთი ფაილი).
- `src/core/` — გამოთვლები, ინტერფეისისგან დამოუკიდებლად:
  - `geometry.js` — ფართი, პერიმეტრი, კედლის სიგრძის შეცვლა.
  - `model.js` — ოთახის დანიშნულებები, კარის/ფანჯრის ტიპები, ნიმუში ბინა.
  - `measure.js` — იატაკი, კედლები ღიობების გამოკლებით, ფილა, ფარტუხი, პლინტუსი, რაფები.
  - `catalog.js` — მასალების კატალოგი: საქართველოს მაღაზიების პროდუქტები, ფასი, ბმული და შემოწმების თარიღი. ფასის განახლება აქ ხდება.
  - `finishes.js` — რომელი მასალა რომელ ზედაპირზე.
  - `quantities.js` — შესაძენი რაოდენობა, დანაკარგი, შეკვრები, დამხმარე მასალები.
  - `furniture.js` — ავეჯის ბიბლიოთეკა (ზომები, კატეგორიები), ნივთის ფორმა გეგმაზე, კედელზე მიკვრა, სამზარეულოს კარადების რიგები.
  - `layout.js` — ავეჯის შემოწმება (გადაფარვა, კედელში შესვლა, კარის გაღება, ფანჯარა, წინ საჭირო ადგილი) და ავტომატური განთავსება.
  - `ids.js` — სტაბილური id-ები ოთახისთვის, კარისთვის და ავეჯისთვის.
- `src/ui/` — გეგმის რედაქტორი, 3D ხედი, მასალები, ხარჯთაღრიცხვა; ავეჯის სიმბოლოები (`furniture-draw.js`), ბიბლიოთეკა (`furniture-library.js`) და 3D-ფორმები (`furniture3d.js`).
- `test/` — ტესტები: გამოთვლები (`core`, `estimate`), დაზიანებული/ხელით შეცვლილი პროექტის ფაილები (`robustness`), ბრაუზერში შენახვა (`store`), ავეჯის გეომეტრია და შემოწმება (`furniture`), ძველი პროექტების გადაყვანა (`migration`) და მიღების სცენარი მონაცემების დონეზე (`interaction`). `test/e2e/acceptance.mjs` — იგივე სცენარი ბრაუზერში (Playwright, დესკტოპი და ტელეფონი).

## აწყობა

საჭიროა Node.js 18+. ერთადერთი dev-დამოკიდებულება `esbuild`-ია; three.js და pdf.js npm-იდან არ იტვირთება.

```
npm ci
npm test        # ყველა ტესტი
npm run build   # dist/artifact.html და dist/site/index.html
node test/e2e/acceptance.mjs [სქრინშოტების საქაღალდე]   # ბრაუზერის ტესტი; სჭირდება Playwright და Chromium
```

ბრაუზერის ტესტი three.js-ს და შრიფტებს CDN-იდან იღებს. ინტერნეტის გარეშე `BINA_LIBS` მიუთითე `node_modules` საქაღალდეზე, სადაც `three@0.128.0`, `pdfjs-dist@3.11.174` და `@fontsource` შრიფტებია.

## მასალები და AI რეფერენსები (ეტაპი 04)

- `src/core/products.js` — ყოველი მასალის პროდუქტის ჩანაწერი: მწარმოებელი, ზომა, ფერი, ზედაპირი, მაღაზია, ფასის თარიღი, **გადამოწმების დონე** (გადამოწმებული / მაღაზიის გვერდიდან / საორიენტაციო / შეფასება / დიზაინის არჩევანი) და მარაგი მხოლოდ მაშინ, როცა შემოწმდა.
- მაღაზიის ფოტოები არ კოპირდება და არ იტვირთება — მხოლოდ პროდუქტის გვერდის ბმულია. ეკრანზე ნიმუში დახატულია და ასეა მონიშნული. ლიცენზირებული ფოტო მხოლოდ `IMAGES`-ით ემატება (`validateImage`).
- `src/core/references.js` — ოთახის მასალების დაფა და AI რეფერენსების პაკეტი (`bina.material-references` v1).
- დეტალები: [docs/stage-04/REPORT.md](docs/stage-04/REPORT.md).

## გამოყენება და ინტერფეისი

- პირველ ვიზიტზე ჩანს მისასალმებელი ეკრანი სამი ნაბიჯით (`src/ui/onboarding.js`); დახმარება — ზედა `?` ღილაკი ან `?` კლავიში.
- 860 px-ზე ვიწრო ეკრანზე გეგმა მთელ ეკრანს იკავებს, პარამეტრები კი ქვედა პანელშია (ჩაკეცილი / ნახევარი / სრული).
- Touch: არჩევა და კედლის გადაწევა ერთი თითით, გადაადგილება და გადიდება ორი თითით; არჩეული ოთახი გადაიტანება მხოლოდ თითის დაჭერა-გაჩერების შემდეგ.
- კლავიატურა: V R P D W, F (ავეჯი), Ctrl+Z / Ctrl+Shift+Z, Ctrl+D (ავეჯის ასლი), Delete, ისრები (1 სმ, Shift — 10 სმ), Esc, Enter.

## ავეჯი და 3D

- ბიბლიოთეკა: დივანი, სავარძელი, ჟურნალის მაგიდა, ტელევიზორის ტუმბო; საწოლები, კარადა, ტუმბო; სასადილო მაგიდა, სკამი, სამუშაო მაგიდა; სამზარეულოს კარადები, მაცივარი, ქურა, ნიჟარა; უნიტაზი, ვანა, საშხაპე, ნიჟარა კარადით. ზომები ცვლადია.
- ნივთი ოთახის თავისუფალ ადგილას ჩნდება (კედელთან, საჭიროებისას სხვა ნივთის გვერდით: სკამი მაგიდასთან, ტუმბო საწოლთან). შემდეგ გადაიტანება, ბრუნდება (15° ბიჯით ან კედლის პარალელურად), ზომა ეცვლება გვერდის სახელურით ან პანელში (სმ).
- მიკვრა კედლებზე და 10 სმ ბადეზე ირთვება/ითიშება; Alt გადათრევისას დროებით თიშავს მას.
- შემოწმება ხაზგასმით და პანელში: ნივთები ერთმანეთს ფარავს, კედელში შედის, კარის გაღებას უშლის, ფანჯარას ფარავს, ან წინ საჭირო ადგილი (მაგ. კარადის წინ 70 სმ) არ რჩება.
- ოთახის გადაადგილებისას ავეჯი მასთან ერთად მოძრაობს; კედლის გადაწევისას კედელთან მდგომი ავეჯი კედელს მიჰყვება; ოთახის წაშლა მის ავეჯსაც შლის.
- სამზარეულოს კარადების რიგი ავეჯია: კედელთან მდგომი რიგი ხარჯთაღრიცხვაში სამუშაო ზედაპირს, ფარტუხს და პლინტუსს ცვლის; კუნძული — მხოლოდ ზედაპირს. აბაზანის „ნიჟარა კარადით“ ნიჟარის ქვის ზედაპირის ფართს განსაზღვრავს.
- 3D ხედი იმავე მონაცემებს იყენებს: ხედი „მთელი ბინა“, „ზემოდან“ ან „ოთახში“ (თვალის სიმაღლიდან, ოთახის კუთხიდან, კარები დახურულია, ჭერი ჩანს) და „კედლების ჭრილი“.

## პროექტის ფორმატი

პროექტი JSON-ია, ვერსიით (`version`, ახლა 2):

- `rooms` — ოთახები (`id`, `purpose`, `points` მეტრებში, სიმაღლე), `openings` — კარები და ფანჯრები კედელზე (`roomId`, `edge`, `offset`, ზომები). კედლები და ღიობები ავეჯისგან დამოუკიდებელი, ძირითადი მონაცემია.
- `furniture` — ავეჯი: `{ id, type, category, roomId, x, y, w, d, h, rot }`. `x, y` ნივთის ცენტრია მეტრებში (იგივე კოორდინატები, რაც ოთახებს აქვს), `w` სიგანე, `d` სიღრმე, `h` სიმაღლე მეტრებში, `rot` ბრუნვა გრადუსებში საათის ისრის მიმართულებით; ნივთის წინა მხარე ლოკალურ +y-ზეა, უკანა (კედლისკენ) — −y-ზე.
- ვერსია 1-ის პროექტები ავტომატურად გადადის: სამზარეულოს კედლის მონაკვეთები (`room.kitchen.runs`) `kitchen_run` ავეჯად იქცევა, ზომები და ხარჯთაღრიცხვა უცვლელი რჩება.

## შენახული მონაცემების უსაფრთხოება

- ბრაუზერში შენახული ან ფაილიდან გახსნილი პროექტის ყველა მნიშვნელობა მოწმდება (`migrateProject`). გამოუსწორებელი ოთახი ან კარი/ფანჯარა გამოიტოვება და მომხმარებელი ამას შეტყობინებით ხედავს.
- თუ შენახული პროექტი საერთოდ ვერ იკითხება, ის ჯერ `bina-designer:project:unreadable-backup` გასაღებით რეზერვდება და მხოლოდ შემდეგ იხსნება ნიმუში.
- ცვლილება ინახება გვერდის დახურვის ან ფონზე გადასვლისას; შენახვის შეცდომა (სავსე მეხსიერება) მაშინვე ჩანს.
- გეგმის სურათად მიიღება მხოლოდ ჩაშენებული PNG/JPEG/WebP/GIF (`data:` URL).

3D (three.js r128) და PDF-ის გახსნა (pdf.js 3.11.174) cdnjs-დან იტვირთება მხოლოდ საჭიროებისას.

## გამოქვეყნება

ეს პროექტი დაკავშირებულია Cloudflare Pages-ის არსებულ **bina** პროექტთან GitHub-ის ნატიური ინტეგრაციით.

- GitHub repository: `apkhadzeangio/bina` (branch: `main`).
- Cloudflare Pages project: `bina`.
- Framework preset: **None**.
- Build command: **ცარიელი** (საიტი წინასწარ არის აგებული).
- Build output directory: `dist/site`.
- Pages URL: https://bina-csn.pages.dev
- Custom domain: https://bina.lithos.ge

`main` ბრენჩზე ყოველი ახალი push ავტომატურად იწვევს Cloudflare Pages-ის production deployment-ს. GitHub Actions-ის ცალკე Wrangler workflow და Cloudflare API token secrets აღარ არის საჭირო.

კოდის შეცვლის შემდეგ გაუშვი `npm test` და `npm run build`, შემდეგ commit/push გაუკეთე აგებულ `dist/site/index.html`-საც.
